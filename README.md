# Demand Forecasting API Functional Tests
This repository contains a standalone pytest functional test suite for testing the electrical demand forecasting APIs developed for the FEDECOM Project. 

The test suite sends real requests to the APIs deployed on the FEDECOM platform and verifies that they:
- are reachable
- accept valid requests
- reject invalid requests appropriately
- return the expected response structure
- return the expected number of forecasting points
- return valid timestamps
- return forecasts at the expected time interval
- return valid numerical forecast values
- return appropriate response for missing data
- meet API response time expectations

The purpose of these tests are to validate that the deployed forecasting services behave as intended rather than test the internal implementation of the APIs.

## Project Structure
The project is organised into separate test files for each demand forecasting API, with shared pytest configuration and project documentation. 

`tests/`

Contains the functional tests for each API: 
- `test_forecasting_api_aic.py`
- `test_forecasting_api_enbro.py`
- `test_forecasting_api_gd_lic.py`

The majority of the functional tests cover common behaviour across the three forecasting APIs. API-specific tests are kept in the relevant test file. 

`conftest.py`

Contains the shared pytest fixtures used by the test files. These fixtures provide configuration regarding API URLs, API Key and valid request payloads. 

`pytest.ini`

Contains the pytest configuration of the project, in this case the location where pytest should look for test files.

`requirements.txt`

Lists the python packages required to run the functional test suite. 

`.gitignore`

Specifies files and directories that should not be committed to the repository. 

`README.md`

Provides documentation for the project. 

## Requirements
To run these test, the following are required:
- Python 3
- pytest
- requests
- Access to the APIs being tested
- Valid API Key
- Valid payload configuration for each API

The APIs may be running locally in Docker or deployed to the FEDECOM platform. 

## Configuration
The test suite uses environment variables for API-specific configuration. Configuration includes the API URL, API Key and valid test request information. Before running the tests, the required environment variables must be set. 

Example PowerShell configuration:

```
$env:FORECASTING_API_KEY="..."
$env:FORECASTING_API_URL="..."
$env:FORECASTING_API_URL_AIC="..."
$env:FORECASTING_API_METER="..."
$env:FORECASTING_API_SITE="..."
$env:FORECASTING_API_METER_AIC="..."
$env:FORECASTING_API_SITE_AIC="..."
$env:FORECASTING_API_LOCATION="..."
$env:FORECASTING_API_START_TIME="..."
```
## Running the tests
From the project root run:

`pytest -v -s`

This runs **all** the tests discovered under the `tests` directory. The parameter `-v` runs pytest in verbose mode and displays individual tests and results. The parameter `-s` displays any output generated by `print()` statements within the tests (for example the API response time).

To run the tests for an individual API, run: 

`pytest -v -s tests/test_forecasting_api_aic.py` , `pytest -v -s tests/test_forecasting_api_enbro.py` or `pytest -v -s tests/test_forecasting_api_gd_lic.py`
